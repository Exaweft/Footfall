[1.0.0] - not yet released

Added

  • Package skeleton: Runtime and Editor assemblies, EditMode test assembly, and Tools > Exaweft > Footfall > About.
  • Documentation: a user guide with a five-minute quick start (Documentation/index.md) and an API overview (Documentation/api.md). Both are online at https://exaweft.github.io/footfall/.
  • Exaweft branding: a footprint logo (drawn in code, no image asset) on the Sessions window tab and header band and the collapsed Scene View panel. The panel and the Sessions window use Exaweft's palette (navy on the dark skin, a pale mint tint on the light skin): the panel's sections are cards with a mint edge, mint headings and coloured count chips, and the fields, toggles, slider, buttons, toolbar and session table inside them are restyled to match. The look is one stylesheet scoped to Footfall's own UI, so the rest of the Editor is unchanged. A panel opened while Unity is still importing the package picks the look up as soon as the stylesheet arrives.
  • The Footfall panel's settings and the export folder are remembered per project, so one game's event names don't carry into another.
  • Damaged session files are read safely: a track ID far out of sequence, or a time or position that isn't a finite number (or a negative time), skips that line instead of breaking the import, and any file that can't be read is listed as failed without stopping the others. A cap record's time counts towards the duration of a session cut off before its end.
  • Heatmaps.Record and the recorder skip positions that aren't finite numbers, with one warning per run, and an OutputFolder a path can't hold turns recording off with a warning instead of throwing into the game.
  • Top View picks its plane from events as well as movement, so a 2D game that records only events is framed on XY.
  • Heatmaps.Record(name, position) with optional tags, as one key and value or as ("key", "value") tuples.
  • HeatmapRecorder component: samples its GameObject's position every 0.5 s of game time (adjustable) as a track.
  • Session files (format version 1): one plain-text file per session under Application.persistentDataPath/Footfall/Sessions, with a JSON header (session ID, scene, build version, platform, tester label, start time) and one record per line. Values read back exactly.
  • Sessions end when the active scene changes, when the game quits or leaves Play Mode, or on Heatmaps.EndSession.
  • SessionFile.Read reads a session, including one still being written or cut off by a crash.
  • Caps on position samples (100,000) and events (20,000) per session, kept separately.
  • Recording is off in release builds unless Project Settings > Exaweft > Footfall > Record in release builds is ticked (the FOOTFALL_RECORD_IN_RELEASE scripting define).
  • Tester labels from Heatmaps.TesterLabel or the -footfallTester command-line argument.
  • Heatmaps.Paused: ignore records and samples for a while (menus, cutscenes, or until a tester agrees to recording) without ending the session.
  • Tools > Exaweft > Footfall > Sessions window: import a session file, a whole folder (subfolders included) or the Editor's own sessions; filter by scene, build version, tester, date range and event type; and see each session's start, duration, events and deaths, with totals for the filtered list. The list of imported files is kept per user in UserSettings/Footfall and reloads with the Editor. Bad files are skipped with a Console message, and copies of a session already loaded are skipped.

  • Scene View overlays, drawn with Handles so they work in 2D and 3D and with any render pipeline:

    • Points: a marker at each recorded event, coloured by event type ("death" is always red), with a legend in the Footfall Scene View panel. Click a legend entry to hide or show that type.
    • Trails: each session's movement path. The session selected in the Sessions window is drawn bright and the rest faded. Long trails are thinned for drawing.
    • Replay: pick a session in the panel (or double-click it in the Sessions window) and drag the scrubber or press Play (1x to 16x) to watch the run: the path draws up to the current time, a ring shows where the player is, and events appear as they happen.
    • Click a marker to see its event, time and tags, and the session's tester, start time, scene and build.
    • Tag breakdown and filter: pick a tag in the panel (such as wave) to count the shown events by its values and event type, in natural order (2 before 10). Pick a value as well to show only those events in the markers, legend and event density.
    • Only sessions recorded in the open scenes are drawn, unless This scene only is turned off. A session matches an open scene by its path, or else by its name, so a scene that has moved (or a sample imported to another folder) still shows its sessions.
    • Density: a grid heatmap on the ground plane (XZ for 3D, XY for 2D, or Auto), counting one event type or movement (position samples), with cell size, colour ramp (Heat, Viridis, Red) and opacity controls. The busiest cell is always the top colour. Drawn as a single mesh with the Handles shader, so it needs no render pipeline. On levels with stacked floors, a cell's points more than Floor gap apart in height (2.5 units by default) are counted as separate floors, each drawn at its own height; 0 draws one flat grid.
    • Top View looks straight down on everything drawn (straight on, for 2D).
    • Export PNG saves the Scene View's camera picture with the Footfall overlays at the view's resolution, ready to share. Editor-only drawing (the grid, gizmos and floating panels) is left out.
  • Demo sample (Samples/Demo): "The Crossing", a 3D level built from primitives in any render pipeline, simulated players that record trails and deaths, and eight ready-made sessions.
